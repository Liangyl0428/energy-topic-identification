# 运行配置与输入清单

P0 已将当前 `pipelines/full_nmf/` 主流程，以及成熟度上下文编码入口，接入 [runtime_paths.json](../config/runtime_paths.json)。共享加载器为 [runtime_config.py](../runtime_config.py)。数据路径和代码路径分开：`data_root` 指向大数据/缓存所在位置，`delivery_root` 是本份 `final` 代码包所在位置。

## 路径配置

默认配置的 `data_root=../..` **相对于配置文件所在的 `final/config/` 解析**，因此在当前工作区指向项目根目录。所有相对路径都按配置文件位置解析，不受启动目录影响；不再在代码中猜测 `final` 下是否存在 `jjjj/aaaa/analyze`。

把整个 `final` 交给开发团队时，请一起保留 `runtime_config.py`、`config/`、`tools/` 和三个模块。它们组成全量流水线运行包。单独安装热点或成熟度基础 Python 包仍可使用其原有本地功能；全量脚本还需要本运行包与外部数据资产，不能只复制某个脚本。

可以直接修改配置文件，或使用环境变量覆盖：

| 配置项 | 环境变量 | 用途 |
|---|---|---|
| 配置文件本身 | `ENERGY_PLATFORM_CONFIG` | 指向另一份 JSON 配置 |
| `data_root` | `ENERGY_DATA_ROOT` | 原始数据和已有大缓存所在根目录 |
| `raw_data_dir` | `ENERGY_RAW_DATA_DIR` | 原始 `data/` 路径，仅用于输入说明与预检 |
| `corpus_dir` | `ENERGY_CORPUS_DIR` | 冻结 `part-*.parquet` 所在目录 |
| `metadata_db` | `ENERGY_METADATA_DB` | 论文机构/引用元数据库，始终只读打开 |
| `keyword_sources` | `ENERGY_KEYWORD_SOURCES` | 关键词原始 CSV 清单 |
| `bge_model_dir` | `ENERGY_BGE_MODEL_DIR` | 模型及 tokenizer |
| `bge_runtime_dir/bge_core_dir` | `ENERGY_BGE_RUNTIME_DIR/ENERGY_BGE_CORE_DIR` | 项目既有 ONNX 运行时及 Python 依赖目录 |
| `classification_run` | `ENERGY_CLASSIFICATION_RUN` | 分类完成结果或新的计算目录；兼容 `FULL_NMF_RUN`，后者优先 |
| `hotspots_run` | `ENERGY_FULL_HOTSPOTS_RUN` | 当前热点全量结果目录，与旧回放环境变量区分 |
| `maturity_run` | `ENERGY_MATURITY_RUN` | 成熟度映射输出目录 |
| `context_dir` | `ENERGY_CONTEXT_DIR` | 对象上下文与已编码向量 |

环境变量路径建议使用绝对路径；相对值同样相对于配置文件位置。输入缺失时预检会报告配置键与实际解析路径，不会下载或伪造数据。

关键词清单内部原有绝对路径。配置中的 `source_path_prefixes` 明确声明旧路径前缀到新 `data_root` 的映射，准备阶段按此重定位 `path`；不会只取文件名猜测位置。若将原始数据放到另一种目录结构，需要同时修改前缀映射或提供更新过的清单。原始清单本身保持不变。

## 先做只读预检查

在项目根目录运行：

```sh
.venv-hotspots/bin/python final/tools/check_inputs.py
```

迁移到其他服务器时，使用已安装 CPU 依赖的 Python，并指定数据根目录：

```sh
ENERGY_DATA_ROOT=/data/energy-project python /delivery/final/tools/check_inputs.py
```

输出 [INPUT_MANIFEST.json](../provenance/INPUT_MANIFEST.json) 记录实际配置、输入路径、日期范围、来源数量、紧凑文件的 SHA-256、外部资产是否存在、元数据库字段，以及三个交付模块是否绑定同一份分类摘要。语料分片内容和大元数据库未在预检中全量重新哈希；报告明确保留这一限制。生成的绝对路径表示运行当时的位置，不是搬迁后仍然有效的固定路径。

`windows` 是冻结结果的口径说明，**不是可自由调节的评分参数**。修改时间窗口后需要另建计算版本；预检会拒绝与本版结果不一致的窗口，不能只改文档就把旧结果当作新窗口结果。

## 本次 P0 的轻量复现

只重建 122 条成熟度交付，不需要全量语料、GPU、外部模型或重训主题：

```sh
.venv-hotspots/bin/python final/energy-technology-trl-crl/pipelines/full_nmf/build_crl_reason.py
```

该入口保留了原文件名以兼容已有调用，但行为已修正为“按现有引擎重算等级、分开导出说明、同步主题主表”。可用 `--data/--source/--out/--catalog` 指定输入输出。重复运行不应改变等级、丢失历史名称或把说明重新写入数值列。

## 全量运行入口

当前 `classification_run` 默认指向工作区中已经完成的缓存。需要独立重跑时，先把它改到**新目录**，避免覆盖已有检查点；同时配置输出和依赖，并按模块文档执行。修改路径不意味着必须重跑 511 万条记录。

```sh
.venv-hotspots/bin/python final/energy-topic-identification/pipelines/full_nmf/run.py
.venv-hotspots/bin/python final/energy-topic-hotspots/pipelines/full_nmf/build.py --help
.venv-hotspots/bin/python final/energy-technology-trl-crl/pipelines/full_nmf/build.py --help
```

热点 `build.py` 和 `experiments.py` 还支持 `--metadata-db` 直接覆盖元数据库。下游分类、热点、上下文和输出目录均可由原 CLI 参数覆盖配置默认值。全量运行器调用本 `final` 内的模块代码，数据从配置定位。

本次没有执行全量重训、重新评分或发布。`after_full.py/resume_delivery.py` 是另行授权的历史发布调度入口，不属于 P0 验收命令；不要用它们代替本地预检。
