# 模块接口与展示规范

> 本文描述 P0/P1 契约。当前业务展示优先采用 [P2 使用手册](P2业务主题与决策使用手册.md)及 [P2 接口说明](P2接口与复现说明.md)；原 F500 和 P1 字段继续保留。

本轮在三个现有模块的 `assets/full_nmf500/p1/` 下新增业务输出。保留原 F500 主表、成员、热点数值及成熟度判级；新增字段和样例作为平台接入层。优先读取 JSON，CSV 用于审阅，嵌套数组/对象以 JSON 字符串保存。

## 页面四块内容

1. **主题业务说明**：业务名称、原 F 编号和算法名称、定义、应用场景、纳入/排除范围、审核状态。业务分类标签取自已审样本时，必须显示其依据；不能据此对整个聚类汇总业务规模。
2. **趋势洞察**：`judgment`、`narrative`、`key_numbers`、`recommended_actions`、`limitations`、`windows`。主标题旁固定显示“原算法聚类／范围待审”。分数及候选排名只能在候选分析区使用，不能伪装成已批准的业务排行榜。
3. **具体对象成熟度**：对象名、配置、用途、边界、证据期间、截止日、两轴等级/状态、阶段解释、下一步行动和缺口。仅 `paired_axes_usable=true` 的同对象记录进入双轴散点图。
4. **证据与待办**：文献和对象的原文引用、来源跳转、审核人类型、下一阶段待核查要求。门槛状态 unknown 表示未核实，不等于测试失败；null 等级不得转为 0。

主题案例分布按当前主候选关联统计，每个对象只计一次；Top3 语义检索候选没有额外重复加入。没有案例时显示“暂无关联证据”，不能显示成熟度低。多个业务标签汇总文献时按 doc_id 去重，分类人数不能简单相加。

## 关联和引用

同一 `taxonomy_version=full_nmf500_20260926` 下，用 `category_id` 连接主题、原聚类洞察和案例分布。用 `business_topic_id` 连接已审成员与重算样本统计；用 `case_id` 连接对象与门槛。业务层版本为 `energy_business_p1_20261018`。

趋势 `evidence_refs` 中，`artifact` 相对 `final/`，`record_key` 是实际筛选键，`fields` 指明引用列。开发端按这些键定位结果表，而不是把对象当作网页 URL。成熟度可从 supported_gate_ids → gate_id → observation_ids → evidence_id → source_id 逐层打开。

```python
import json
from pathlib import Path

root = Path('final')
def rows(module, name):
    return json.loads((root / module / 'assets/full_nmf500/p1' / (name + '.json')).read_text())

topics = {r['category_id']: r for r in rows('energy-topic-identification', 'topic_business_cards')}
insights = {r['category_id']: r for r in rows('energy-topic-hotspots', 'topic_insights')}
topic = topics['F0110']
signal = insights['F0110']
assert topic['taxonomy_version'] == signal['taxonomy_version']
assert signal['population_scope'] == 'original_algorithm_cluster'
```

外部来源链接只接受 http/https，正文和原始题名作为纯文本渲染。CSV/Excel 是审阅副本，精确原文与整数/null 契约以 JSON 为准。

## 状态与发布规则

| 字段或状态 | 展示含义 |
|---|---|
| `unreviewed` | 未做主题业务审核 |
| `partial_assistant_review_pending_domain_review` | 助手审阅了部分文献，完整主题尚待领域审核 |
| `assistant_reviewed_pending_domain_review` | 具体样本已有助手初审，尚非独立专家批准 |
| `include` | 纳入本轮指定业务子主题；不自动传播到整个 F 聚类 |
| `outside_current_energy_scope` | 所给文本不属于本轮能源业务范围，原始记录仍保留 |
| `insufficient_evidence` | 暂无法判断，进入补证队列，不能作为无关样本统计 |
| `numeric_facts_checked_scope_pending` | 数字可回溯，范围尚待审定 |
| `candidate_mapping_pending_review` | 对象与主题的语义关联候选 |
| `rank_eligible=false` | 不允许进入已批准业务热点排名 |

目前无完整主题的 `scope_approved=true`。不能仅改状态使主题通过审核；需要对应的成员快照、范围结论、负责人及审核日期。整体剔除、拆分或合并时，建立新成员版本，重算季度、机构、分母和热点评分，旧 F 编号与映射继续保留。本轮只重算 24 条定向诊断样本中的 11 条纳入记录；原主题趋势卡不反映这次样本拆分。

## 运行和维护

在项目根目录运行（依赖 pandas、openpyxl；P0 运行环境已具备）：

```bash
.venv-hotspots/bin/python final/tools/build_p1.py
.venv-hotspots/bin/python -m pytest final/tests/test_p1_delivery.py -q --import-mode=importlib
.venv-hotspots/bin/python final/tools/refresh_p1_manifests.py
.venv-hotspots/bin/python final/tools/validate_p1.py
```

构建完全本地化，复用交付内的小型文本/机构快照与已有汇总，不访问外部大模型，不重新训练主题模型。增量审核输入位于 `energy-topic-identification/data/business_review/`，包括定义、决策、文本及来源指纹。不要把研究者或专家姓名填入未实际参与的审核记录。当前 reviewer_type 固定记录为 assistant。

更新输入后需重新生成下游文件并运行验证。若更换分类快照，先更新真实文献成员、对应证据及版本绑定，不能仅修改哈希绕过校验。生产全量统计仍使用原 full_nmf 管线和显式路径配置；P1 的 reviewed_scope_metrics 是定向样本重算接口，不能当作全量流水线。

解释采用确定性事实模板，`generation_method` 记录模板版本，`model/prompt_version=null`。后续如使用大模型，只能在冻结的数字、对象和引用范围内润色；输出必须保留引用、范围和状态，并重新校验数字。缺失的业务事实不能由生成文本补齐。
