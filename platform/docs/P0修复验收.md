# P0 修复验收

本轮直接修复三个现有模块的交付契约与运行配置，不再扩展主题发现试验。未修改原始证据、量表规则、分类模型、主题成员或热点分数；没有外部大模型调用、提交或发布。

## 已修复

| 问题 | 修复结果 |
|---|---|
| 等级列混入 `TRL4` 和中文缺口 | TRL/CRL 分别为 1—9/1—5 的整数或空值；JSON 为原生整数/null |
| 缺证据说明没有独立字段 | 增加轴状态、阶段名称、冲突标记、缺口、解释及展示文本 |
| 主题 ID 更新而名称仍旧 | 122 条记录全部按当前 F500 主表同步；旧 ID/名称/多值字段单独保留 |
| 下次 build 会覆盖修复 | 全量 build 和兼容后处理入口共用导出函数；隔离目录中的真实输入重建用于验收 |
| 运行代码依赖目录猜测 | 现行全量流程读取统一路径配置；数据目录与交付代码目录分开；清单内部路径支持显式前缀重定位 |
| 数据批次和时间窗口不清 | 增加平台字典、实际输入清单和三模块复现说明；区分来源日期、热点窗口与成熟度截止日 |

修复后仍有 TRL 已知 108、未知 14，CRL 已知 23、未知 99，双轴都有证据的对象 13 个。未知没有转成 0；正式等级和主题整体等级仍为空。名称一致只解决关联错误，不代表这些算法主题已通过业务范围审核。
