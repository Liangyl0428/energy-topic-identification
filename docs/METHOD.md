# 这些主题是怎么整理出来的

这 750 个主题是在初始聚类的基础上，经过合并重复类别、细分宽泛类别，再统一整理得到的。主要过程是：**500 类底稿 → 合并为 486 类 → 参考 1000 类候选细分 → 486 个保留类别 + 264 个实际使用的细分类 → 750 类目录**。仓库按功能保留了文本编码、主题聚类、分类修订和目录导出代码。

## 先找内容相近的研究

输入包括论文、专利和政策。整理时保留每条记录的题名、正文、来源等信息，并分配一个全局行号 `row_id`，用于在处理前后找到同一条记录。

为了比较不同语言、不同写法的文本，项目使用多语言 MiniLM 模型把文本转换为一组数字，也就是“语义向量”。内容相近的文本通常会得到较接近的向量。长文本分段处理，再把各段的信息合成为一条记录的向量。

在此基础上，将相近记录聚在一起，并提取能够描述每组内容的主题词。项目先形成 500 类底稿，又在同一批语料上进行了 1000 类候选试验，以便从更细的粒度观察研究方向。这两套聚类结果在后续整理中承担不同作用。

如果关注模型细节：向量经过 PCA 降到 64 维，并做 L2 归一化；BERTopic 使用 MiniBatchKMeans 生成预设数量的候选组，主题词由真实文本的词频通过 c-TF-IDF 提取。训练中论文、专利和政策的权重为 70%、25% 和 5%。这些权重用于训练，不是最终表格中的记录比例。

## 从 500 类到 750 类，具体做了什么

### 先把 500 类中的重复和冗余合并为 486 类

初始 500 类是聚类得到的底稿。不同组有时只是用词、材料表述或文献来源不同，实际讨论的研究对象和任务却很接近。因此，先结合主题词、抽样题名和可用正文片段，检查哪些类别可以合并。

这一轮共接受了 **13 组合并，类别数量净减少 14 个，得到 486 类**。减少的是重复或难以稳定区分的类别，相关文献仍保留，并归入合并后的类别。合并记录见[原始审阅摘要](../provenance/original_audit/MERGE_REVIEW.json)。

例如，部分电力设备和线路故障诊断的聚类被合并到同一个较宽的方向下。合并先处理类别之间的重合，但合并后的方向里仍可能包含多个具体任务，需要继续细分。这也解释了为什么整理过程中既有“合并”，又有“细分”。

### 再参考 1000 类候选，细分 486 类中较宽泛、混杂的方向

1000 类候选是在同一批语料和向量上重新进行的全局聚类，用来帮助发现更细的研究对象和任务。它与原类别可以交叉对应，不能理解成把每个原来的 500 类简单一分为二。

后续以 **486 类目录为基础**，重点处理其中 **280 个宽泛或混杂类别**，参考 1000 类候选的主题内容、代表文本和语义向量，提出细分类规则。具体记录是否进入细分类，还要经过对象/任务匹配、语义支持和误匹配检查。证据不足的记录可以保留原类别，并标记待复核。

这意味着，1000 类提供的是细分线索。最终采用哪些细分类，要以规则和实际归类结果为依据。

### 把实际使用的类别整理为 750 行目录

经过分类修订，正式结果中仍有记录直接归入的原类别共 **486 个**，实际启用的细分类共 **264 个**。因此，最终目录的数量是：

**486 个保留类别 + 264 个实际使用的细分类 = 750 个主题。**

原类别保留的是仍直接归入该类别的记录，已进入细分类的记录按细分类计数。例如，一篇记录进入某个更具体的故障诊断主题后，就只计入这个主题，不再在原宽泛类别中重复累计。750 类表因此是按直接归属整理出的平级列表。

| 阶段 | 类别数量 | 这一阶段解决的问题 |
| --- | ---: | --- |
| 初始聚类底稿 | 500 | 先把内容相近的研究分组 |
| 去重合并后的基础目录 | 486 | 合并已确认重复或难以稳定区分的类别 |
| 独立的细粒度候选聚类 | 1000 | 为宽泛类别的细分提供线索 |
| 最终统一目录 | 750 | 汇总 486 个仍有直接记录的类别和 264 个实际使用的细分类 |

两种粒度的训练代码统一放在 `topic_modeling/` 中，分别由 `train_baseline.py` 和 `train_candidates.py` 运行；文本编码放在 `embedding/` 中。具体输入和命令见[编码和主题聚类](EMBEDDING_BERTOPIC.md)。

## 再检查“研究什么、做什么”

聚在一起的文本仍可能讨论不同问题。因此，分类还需要看具体研究对象和研究任务，并参考代表性文本、相近主题及既有审阅意见。

例如，“研究电池材料”和“使用电池为设备供电”都可能出现“电池”一词，但关注的研究问题不同。规则会同时检查对象和任务，结合语义相似程度决定是否接受某个类别。这个例子用来说明判别思路，具体条件以代码中的规则为准。

处理过程中还会清理文本模板，识别题名摘要不足、无法使用的正文，以及封面、索引等内容。对于多个任务同时出现、只有背景提及、证据不足等情况，程序会保留复核标记。另有一轮检查专门拦截已发现的误匹配，例如不能因为 `relationship` 中包含 `ship` 一类字母片段就判断为船舶研究。

因此，一条记录可能已经有当前类别，同时仍标记为“待复核”。有些标签沿用此前结果，有些是根据规则调整的，结果表保留了这些区别。

## 最后整理为 750 个主题

上述 486 个保留类别和 264 个实际使用的细分类，最终统一编号为 `C0001` 至 `C0750`。没有实际记录的候选不进入这张表。

统计按每条记录最终直接归入的类别计算，每条已归类记录只出现一次。这样就不会把一条细分类记录再算到原主类里。因文本质量问题单独处理的记录不占用研究主题编号。

这一轮统一目录和编号，没有重新改变记录所属的研究方向。此前已经完成的 374,161 条研究主题调整，以及文本清理和复核标记，都保留在结果中。

## 结果能说明什么

这份目录可以用于浏览研究方向、查看当前分类数量，以及继续开展主题审阅。它基于自动处理和抽样检查，目前仍有约 276 万条记录待复核。

文件校验可以确认编号连续、数量相符和文件内容一致。分类是否准确、相邻主题是否仍有重叠，需要另外评估。当前没有独立的人工标准答案来计算整体准确率，750 个主题名称不同也不意味着它们在语义上完全没有交叉。
